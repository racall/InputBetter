# 2026-10-17 08:47 — 字幕翻译重新设计：只在「译」菜单里开关、翻译方式单独切换、边说边译不丢句、6 家在线翻译、字幕记录可单独翻译

## 为什么改

用户反馈：
- 菜单栏「字幕翻译（简体中文）」、字幕条「显示译文」、设置里的「显示译文」其实是同一个开关，文案和交互都让人困惑；开过一次就被记住，下次开字幕会自动翻译。
- 字幕条上没法快速切换翻译方式和模型。
- 只有系统翻译和 AI，希望接入主流的在线机器翻译。
- 字幕结束后，记录窗口里的字幕没法单独翻译。
- 希望译文跟得上原文、不丢句子、准确，还读得过来。

## 改了什么

### 开关与交互
- 翻译只在字幕条「译」菜单里开启：菜单只列语言（含「自动」），选一个语言即开启，再点当前打勾的语言即关闭。
- 开关只对本场字幕有效：`SubtitleController.translationEnabled` 每场开始时关闭，不再持久化。
- 删除菜单栏的「字幕翻译」项；设置 › 实时字幕的「显示译文」开关改为说明和「翻译设置…」按钮。
- Passport 上键仍是同一个开关（`subtitles.toggleTranslation()`）。
- 翻译方式单独一个标签（`TranslationMethodChip`），开启翻译后出现在「译」标签旁边，菜单内容：
  - 系统翻译；
  - 已配置的在线服务；
  - AI 大模型，直接列出该服务的模型（`LLMModelCatalog` 缓存模型列表）；
  - 添加在线翻译服务（点了打开 设置 › 翻译 并直接弹出配置表单）。
- 当前方式不可用、或翻译出错（额度、密钥等）时，在译文位置说明原因。

### 一次只用一种翻译方式
- `TranslationEngine`（系统 + AI 润色 / 仅系统 / 仅 AI）换成 `TranslationMethod`（system / provider / llm(model:)），去掉混合模式。
- 启动时迁移旧设置：hybrid / system → 系统翻译，llm → AI；并删除旧键 `translationEngine` 和 `subtitleTranslate`。
- `TranslationService` 重写为按方式分派，接口有：
  - `translateLine`
  - `translateBatch` / `plan` / `translateChunk`
  - `draft`
  - `refine`
  - `translateDictation`
  - `isAvailable(method)` / `unavailableReason`
- 听写翻译也使用所选方式。

### 边说边译、不丢句
做法参考 Google 的重翻译与稳定前缀研究（Arivazhagan 等 2020）：
- `LiveDraft` 把正在说的半句按节流策略（`LiveDraftPolicy`）反复重翻：
  - 系统翻译每 0.3 秒；
  - 在线服务每 1 秒，且原文至少多出 3 个词；
  - AI 不做重翻，改为逐字显示整句译文。
- `DraftStabilizer` 对暂定译文做两件事：
  - 遮住末尾 2 个词（中日韩文字为 3 个字），末尾最依赖还没说出来的原文；
  - 只增不改，已显示的部分不再改写，不会闪烁。
- 暂定译文略暗地接在译文行末尾；整句说完后换成整句译文，每句只替换这一次。
- `RollingCaptions`：
  - 去掉"等 4 / 12 秒没译文就跳过"的逻辑。整句译文迟迟不到（系统 3 秒、在线 8 秒、AI 15 秒）或翻译失败时，用暂定译文顶替，没有暂定译文就显示原文。
  - 只有一句什么都还没有时，后面的句子才等它（才显示「翻译中…」），修复了「翻译中…」一直卡住的问题。
- `SentenceTranslator`：
  - 字幕条（识别中确认的句子）和字幕记录（定稿的句子）的同一句只请求一次；
  - 60 毫秒内到达的多句合并成一次批量请求。
- `CaptionFeed`：
  - 每段话开始时锁定路径，修复中途切换翻译方式导致的句子重复；
  - 换语言或方式时用代数丢弃旧结果，修复旧译文晚到、覆盖新译文的问题。

### 在线机器翻译（新增 `Translate/MachineTranslation/`）
- 接入 6 家：DeepL、Google Cloud Translation（v2）、微软 Azure Translator、火山引擎、腾讯云 TMT（TextTranslateBatch）、百度翻译。
- 每家实现 `MachineTranslator`，拆成 `makeRequest`（构造请求）和 `parse`（解析响应）两部分，便于测试。
- 签名放在 `Support/Signing/`：
  - `SigningCrypto`：CryptoKit 的 HMAC-SHA256 / SHA256 / MD5；
  - `VolcengineSigner`：火山引擎签名；
  - `TencentTC3Signer`：腾讯云 TC3-HMAC-SHA256 签名。
- `ProviderLanguageCodes`：各家的语言代码对照表。
- `MachineTranslationError`：把错误分成可重试和应停止整批两类。限流或临时故障重试一次；密钥、额度、时间错误直接停止并提示。
- `BatchPlanner` 分块：
  - 本机识别源语言，把「自动」解析成具体目标语言；
  - 原文已是目标语言的句子不发请求；
  - 按语言对分组，再按各家的句数和长度上限切块（百度按 UTF-8 字节计算）。
- `RequestGate`：按服务限制并发数和 QPS，字幕和字幕记录共用。
- `MachineTranslationStore`：密钥存本机凭据文件 `translate.<服务>.*`，区域存 UserDefaults。
- 新增设置 › 翻译（`TranslationPane`）：
  - 方式单选列表，每行显示状态和下一步操作（使用 / 配置 / 前往配置）；
  - 目标语言；
  - 边说边译开关；
  - 系统翻译语言包。
- 新增配置表单 `TranslationProviderSheet`：「测试连接」会真的翻译一句并显示译文；第一次配置好的服务自动设为当前方式。
- 原来的「AI 润色与翻译」页改名为「AI 润色」，只保留 LLM 服务和润色设置。

### 字幕记录窗口
- 「字幕」页顶部新增翻译工具条（`TranscriptTranslationBar` + `TranscriptTranslator`），风格与「总结」页的控制条一致：
  - 左侧：「译文：语言」菜单（含「显示译文」）和翻译方式菜单，默认跟随字幕条；
  - 右侧：「翻译 N 句」「AI 润色」，以及 ⋯ 里的「全部重新翻译」。
- 不会自动开始翻译；进行中显示进度，可以取消；字幕进行中和结束后都能用。
- 结果每 0.3 秒批量写回记录（`CaptionTranscript.setTranslations` 先建索引，长记录也是线性时间）。
- 句子记录了译文对应的目标语言和是否已润色，据此计算还需要翻译 / 润色的句数。
- 隐藏译文时，拷贝和保存都不带译文。
- AI 批量翻译用带编号的格式（`Prompts.translateBatch` + `NumberedLines`），编号对不上时改为逐句翻译。AI 润色使用 `Prompts.refineTranslations`。

### 其他
- 新增 `LLMModelCatalog`，「总结」页的模型列表也改用它，删掉了重复的拉取代码。
- 新增调试变量：
  - `IB_TRANSLATE_CONFIG=<服务>`：直接弹出该服务的配置表单；
  - `IB_SHOW_HEADER=1`：字幕条标题栏一直显示，检查排版用。
- 本地化：新增 97 条英文，删除 25 条废弃文案。

## 验证
- Debug 编译通过；`update-strings.sh` 没有缺失翻译。
- 单元测试 150 个全部通过。新增 `TranslationTests`、`MachineTranslationTests`，覆盖：
  - 翻译方式的存储与迁移；
  - 自动目标语言的解析；
  - 分块、编号解析、暂定译文稳定器、边说边译节流；
  - 滚动字幕的暂定译文与顶替；
  - 记录批量写回、请求闸门（并发 / 间隔 / 取消）；
  - 6 家的语言代码、请求构造、签名格式，以及成功和错误响应的解析；
  - 凭据存储。

  签名原语用 RFC 4231 和百度官方文档的测试向量。火山和腾讯的签名只验证了格式和可复现性，没有和官方示例逐字比对。
- 截图检查（只截本 app 的窗口）：设置 › 翻译、腾讯云配置表单、字幕条（含标题栏的两个标签、暂定译文略暗）、字幕记录工具条。
- **没有验证**：
  - 6 家在线服务没有用真实密钥调用过（需要用户提供密钥后，在配置表单里「测试连接」）；
  - 边说边译还没有对着真实视频实测；
  - 菜单的展开状态没有截图。
- 注意：调试构建和正式版共用 UserDefaults。本机运行调试构建时，旧设置已迁移到 `translationMethod`；旧版 app 读不到 `translationEngine`，会回到默认值。
