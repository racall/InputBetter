# 2026-10-16 06:58 — 字幕条按业内做法重做:识别结果稳定化、逐句双语字幕、不丢句;修复按钮点不动

用户反馈:字幕条按钮点了没反应;字幕变化太快读不过来,却又跟不上视频;样式不好看;按钮在宽度动画里漂移;丢句子。要求按业内通用方案解决。

- 实测(Chrome,SenseVoice,系统翻译 + AI):
  - 系统翻译每句约 0.04 秒,AI 润色每句 2–6 秒。
  - 识别引擎每 3–11 秒才定稿一次,每次 100–250 个字符,而原来要等定稿才翻译,所以跟不上;一出来又是一大段并不断重排,所以读不过来。
- 业内方案与实现(`app/InputBetter/Subtitles/`):
  - **识别结果稳定化**(`CaptionSegmenter`,新增):Google / AWS / Azure 的稳定中间结果、Whisper-Streaming 的 LocalAgreement-2——连续两次识别结果开头一致的词(以及紧跟的标点)才算确认,已确认文字只追加、不改写。
  - **断句**(`SentenceSplitter`,新增):只从已确认文字里断句(句末标点;长句在逗号处;短句并入下一句)。规则对只在末尾增长的文字保持稳定,所以句子只增不改,不需要按内容猜对应关系。
  - **定稿对齐**:用已给出部分的最后 3 个词在定稿文字里定位,只补上没给出的句子;引擎分两次定稿时,超出部分留给下一段抵扣。
  - **逐句双语字幕与显示调度**(`CaptionScheduler`,新增;参照 Netflix 字幕规范):一次显示一条(最多 2 行,太长自动缩小字号),按阅读速度停留 1.5–5 秒(约每秒 8 个汉字),显示后不改。落后时每条只停 0.8 秒,并按顺序合并更多句子——从不跳句。
  - **数据源**(`CaptionFeed`,新增):
    - 快速路径(有系统翻译或不翻译):识别中句子一确认就用系统翻译,随即上屏。
    - 只有 AI 时:定稿后按记录的句子显示 AI 译文。
  - **字幕记录改为按句记录**:每句单独翻译,记录窗口和保存的文件里是 AI 润色版。
  - 删除旧的滚动字幕 `RollingCaption`、半句整体实时翻译;`TranslationService.translatePartial` 改名为 `quickTranslate`。
- 丢句子(实测定位):
  - 原因一:落后时「跳过旧句子」,改为合并显示,从不跳过。
  - 原因二:早期按序号对应,一句被引擎改写断句的旧句占住位置,吞掉了后面的句子。
  - 原因三:用新识别结果改写已确认文字,句号改成逗号后产生重复。
  - 改为 LocalAgreement 只追加后,实测核对:每次定稿的内容都恰好被上屏句子覆盖一次,顺序正确。
- 字幕条样式(`Pill/SubtitleSurface.swift`):
  - 背景紧贴文字:宽度随字幕长短变化,高度按实际行数,不预留空位;文字居中;圆角 18。
  - 标题栏(应用名、「译」菜单、工具)只在悬停时出现,改成两步动画:移入先加宽再淡入,移出先淡出再收窄,按钮不再漂移。
- 按钮点不动:原因是字幕文字超出显示框(被裁掉但仍参与点击判定),盖住了顶部按钮。字幕文字改为 `allowsHitTesting(false)`。
- 语言包:英译中需要英语和中文两个语言包,系统会一起下载,这是 macOS 的正常行为;说明文字里写明了这一点。
- 测试:新增 `CaptionPipelineTests`,覆盖断句、断句对增长的稳定性、LocalAgreement 确认、已确认文字只追加、定稿只补未显示部分、措辞有出入时的对齐、多段定稿抵扣、调度停留与不跳句、等译文超时;删除滚动字幕测试。共 109 个测试全部通过。
