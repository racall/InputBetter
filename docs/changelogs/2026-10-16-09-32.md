# 2026-10-16 09:32 — 云端识别新增 Soniox

- 为什么改:用户要求云 ASR 支持 Soniox(https://soniox.com)。
- 改了什么:
  - `ASR/Cloud/SonioxCodec.swift`(新增):Soniox 实时 WebSocket 的编解码,按官方文档实现。
    - 用 `Authorization: Bearer` 头鉴权;配置消息里的 `api_key` 字段已弃用,2027-01-15 起只放在那里会被拒绝。
    - 配置消息:`pcm_s16le`、16 kHz、单声道;字幕开启端点检测(`max_endpoint_delay_ms` 1500),听写不开;`language_hints` 取识别语言,粤语没有单独代码,不加提示;词汇表写进 `context.terms`。
    - 音频用二进制帧发送;结束时发空文本帧。
    - token 处理:最终 token 累加,非最终 token 每次整体替换;遇到 `<end>` / `<fin>` 切出一句定稿;收到 `finished:true` 表示完成;带 `error_code` 时报告 `error_type: error_message`。
    - Soniox 没有「就绪」消息,收到第一条正常响应即视为就绪。
  - `ASR/Cloud/SonioxAPI.swift`(新增):`GET https://api.soniox.com/v1/models` 拉取模型列表,只保留 `transcription_mode == real_time` 的非别名模型。
  - `CloudProvider`:新增 `.soniox`,包括名称、说明、控制台地址、默认模型 `stt-rt-v5`、常用选项;`canFetchModels` 包含 Soniox。
  - `CloudASREngine`:创建 Soniox 会话和拉取模型列表。
  - `CloudConfigSheet`:Soniox 不需要接口地址,填好 Key 后自动拉取模型。
  - 英文翻译 2 条。
- 文档:`README.md`(云端识别表)、`docs/architecture.md`(不重复实现表、§8 调用链、§8a 模型列表)。
- 验证:
  - 单元测试 122 个通过,新增配置消息、结束帧、token 解析、模型列表过滤的用例。`update-strings.sh` 无缺失。
  - 用无效 Key 实测线上接口:WebSocket 握手成功后返回带 `error_code:401` / `error_type:unauthenticated` 的 JSON,与解析逻辑一致;模型列表接口返回 HTTP 401。
  - 没有可用的 Soniox Key,实际识别效果(听写、字幕切句)还没在真机验证,需要用户填入 Key 后试用。
