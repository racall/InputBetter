# 2026-10-16 08:50 — app 不再内置固件,改从官网下载;官网新增 Passport 网页刷写

- 为什么改:用户要求官网上也能刷 Passport 固件,app 内不再包含固件,刷入功能不变,只是改成从官网下载固件再刷入。
- 固件发布(`scripts/package-firmware.sh`,新增):
  - 把 `firmware/build` 整理成 `firmware/build/release/manifest.json` 加 `<version>-<build>/` 下的三个镜像。
  - 检查镜像地址与 `flash_args` 一致、写入范围在 cardid(0x356000)之前,并算 SHA-256。
  - 清单不含任何 esptool 参数。
- app:
  - `Device/Firmware/FirmwareBundle.swift` 改为 `FirmwareManifest.swift`。官网清单的解析与安全校验:芯片 ESP32-C3、地址 < cardid、不重叠、路径只能是清单目录下的相对路径、协议版本必须与 app 一致。`FirmwareError` 新增网络、清单、校验、不兼容、缺少 esptool 几类错误。
  - 新增 `Device/Firmware/FirmwareDownloader.swift`:获取清单(不走缓存),下载镜像到 `~/Library/Caches/InputBetter/Firmware/<ver>-<build>/` 并逐个校验大小和 SHA-256;已缓存的不重复下载。
  - `FirmwareFlasher`:
    - 新增 `.downloading` 阶段,下载时 USB 链路照常工作,下载完才让出串口;
    - 新增 `latest` 和 `checkLatest()`,查询官网最新固件,结果 10 分钟内有效;
    - 写入命令不再带 flash 参数(esptool 默认 keep)。
  - `PassportSetupModel` / `PassportSetupView`:
    - 进入页面时查询官网固件,「有新固件」改为和官网最新版本比较;
    - 显示下载进度;
    - 协议不兼容时提示先更新 app,缺少 esptool 时提示重新安装或改用网页刷写。
  - `AppState` 注入 `FirmwareDownloader`。调试变量:`IB_FIRMWARE_MANIFEST`(换清单地址)、`IB_FLASH_FIRMWARE`(连上 USB 后自动刷一次)。
  - `app/scripts/bundle-device-assets.sh` 只打包 esptool,并清掉旧的 `DeviceAssets/Firmware`。`build.sh` / `release.sh` 总是打包 esptool。`project.yml` 注释同步;版本升到 0.1.2(3)。
- 官网:
  - 新增「在浏览器里刷入固件」一节(`#firmware`),Passport 卡片加了链接。
  - `assets/flasher.js`:Web Serial 加 esptool-js。流程是:选串口 → 下载并校验 → 确认芯片 / 8 MB / 分区表里的 cardid → 可选整片备份下载到本机 → 只写三段(`eraseAll: false`)→ 硬复位。中英文状态提示,刷写中阻止离开页面。
  - 不用 ESP Web Tools:看了 10.4.0 源码,`install-dialog.js` 在全新安装时默认 `_startInstall(true)`,会擦除整片 Flash,抹掉 cardid。
  - esptool-js 0.7.0 的 bundle 和 Apache-2.0 许可证放在 `assets/vendor/`,不走 CDN。
  - `nginx.conf`:`/firmware/manifest.json` 不缓存,镜像长缓存。
  - `deploy.sh`:部署时运行 `package-firmware.sh`,发布 `/firmware/`,最后校验线上清单。
