# 2026-10-17 09:42 — 字幕译文按句分段、平滑滚动、行数可调；设置按场景重新组织(听写 / 实时字幕 / 翻译服务 / AI 服务)

## 为什么改

用户反馈:
1. 看字幕翻译根本跟不上节奏：刚读完前一句，下一句就滚走了；一滚动就不知道自己读到哪里。
2. 翻译服务里的 AI「配置」跳到「AI 润色」页去调接口和模型，这不合理。LLM 配置应该单独出来，AI 润色和翻译各自选模型。
3. 听写翻译里不该放一整行快捷键设置，改成小字提示，点「快捷键」跳转过去。
4. 菜单里的「AI 润色」用户完全不知道是给字幕还是给听写。
5. 要站在项目全局、产品和用户操作路径去考虑。

## 实测与定位(YouTube 实际视频,火山引擎识别 + 系统翻译,IB_CAPTION_TRACE + 只截本 app 窗口)
- 翻译本身不慢：句子确认后，整句译文 0.1–0.2 秒就到。中文译文的增长速度约每秒 4.7 个字。
- 问题出在版式。译文是一整段连续文字，句子从行中间开始；暂定译文换成整句译文后长度会变，后面所有行都跟着重排；每满一行整体瞬间上跳。读者的视线因此找不到原来的位置。

## 改了什么

### 字幕条译文(`Subtitles/RollingCaptions.swift`、`Pill/SubtitleSurface.swift`、`AppSettings`、`PillPanelController`)
- 译文按句分段（`RollingCaptions.translationLines`）：每句单独起一行，正在说的半句是最后一段。
  - 读者的位置总在句首。
  - 一句从暂定译文变成整句译文时，只影响它自己那一段，前面已读的句子不重排。
  - 最多保留 12 句，旧句子整句滚出。
- 新句子出现、或某段大约多出一行时，平滑滚动 0.25 秒。暂定译文逐字变化时不做动画，避免文字一直淡入淡出。
- 亮度按新旧递减：最新一句 1.0，往上依次 0.82、0.68；暂定内容 0.55。滚动后一眼就能看出新内容从哪里开始。
- 行数可调（设置 › 实时字幕 › 显示）：
  - 译文 2–5 行，默认 3；
  - 翻译时原文 0–3 行，默认 2；选 0 时只看译文；译文一个字都还没有时至少显示 1 行原文。
- 字幕条窗口高度 320 → 440，放得下最大字号下 3 行原文加 5 行译文。原文的裁剪阈值调大（900 / 420），避免还没写满框就被裁、框跳动。

### 设置按场景重新组织
- 侧栏：通用 / **听写**(新) / 实时字幕 / 识别模型 / **翻译服务** / **AI 服务** / 快捷键 / 词汇表 / Passport / Vibe Coding。
- **听写**（新增 `Settings/DictationPane.swift`）：
  - 「AI 润色」：开关，加新增的**润色模型**（`AppSettings.polishModel`，空 = 默认模型）。
  - 「听写翻译」：翻译方式、翻译成。
  - 快捷键和词汇表改成说明文字里的链接，点击跳到对应设置页（`inputbetter-settings://<页>`，`View.settingsLinks`）。
- **实时字幕**：在「显示」之后新增「翻译」一节（翻译方式、翻译成、边说边译）。原来指向「翻译设置…」的那一行删掉。
- **翻译服务**（原「翻译」页）：只负责配置服务，场景设置挪到听写页和实时字幕页。两个场景的方式行抽成共用的 `Settings/TranslationScenarioRows.swift`。
- **AI 服务**（原「AI 润色」页）：
  - 只负责 LLM 接口的连接（地址、Key、默认模型）；
  - 下方列出「使用 AI 服务的功能」：听写润色、实时字幕翻译、听写翻译、字幕总结，各自显示所用的模型，「前往」跳到对应的设置。
- 新增共用的模型菜单 `UI/LLMModelMenuItems.swift`，听写润色、翻译方式里的 AI 模型、字幕总结共用。「总结」页原来自己写的模型菜单换成它。
- `SettingsNavigation.configure(_:useFor:)` / `configureSystemTranslation()`：从任何页面配置在线服务或下载语言包，都走同一个入口。

### 菜单
- 菜单栏和胶囊 ⌃ 菜单里的「AI 润色」改为「**听写后 AI 润色**」。没配置 AI 服务时显示「听写后 AI 润色（需要配置 AI 服务）…」，点击打开 AI 服务设置；原来是置灰，点不了。
